# 1.7 冰箱游走推进爆破网

## 单一运行时结构

- `Source/1.7` 构建普通主程序集 `NivarianSleepInFridges.dll`。保留床、设置、事件及存档类型；不引用本体、Lumi 或 RimUnity 程序集。
- 本目录构建固定名称 `NivarianSleepInFridges.OrbitalSupport.dll`，发布到 `1.7/OrbitalSupport/`，不让游戏自动扫描。
- 主模块在 Def 就绪后只尝试接入一次，使用本体已加载运行时。没有自己的 Embedded、载荷、最低运行时声明或哈希匹配。
- Def 初始沿用本体炮弹基类、无 Worker。适配成功后绑定自己的 NivarianSkyfaller 子类及 Worker，并加入本模组程序集列表供 Scribe 查找；失败仅停用新战备。
- 1.6 DLL 保持不变；1.7 使用独立主 DLL，构建时复制共用 Def，不同时加载两份主程序集。

## 构建与部署

依赖 .NET 10 SDK、当前游戏 1.7、Harmony、HAR，以及已安装本体的 Core / LumiParticle。所有引用仅供编译。

```powershell
& ./Source/1.7/Build.ps1
& ./Source/1.7/Build.ps1 -Deploy
```

可覆盖脚本参数中的游戏、本体、Harmony、HAR、SDK 路径。脚本从本体 Embedded 资源提取编译引用到忽略目录；**不导入 Embedded targets，不发布运行时**。两程序集均成功编译后才替换成品。旧发布载荷移动到 `Source/obj/1.7/RetiredArtifacts-*`，可恢复；不改动本体。

部署排除 Source、Git、Tests/Test、缓存、编译引用、log.txt；保留 CHANGELOG.md 与 working.prg。不提交或推送 GitHub。

## 职责与生命周期

- OrbitalSupportHost：一次加载、禁用锁存、退出游戏会话清理。主／适配接口只使用自身和游戏类型。
- OrbitalSupportBackend：初始化本体 Lumi、校验字段与补丁签名、绑定 Def、安装和撤销自身补丁。
- Skyfaller_FridgeBomb：读取本体保存的炮弹动作，不复制运动、跃迁、拖尾或爆炸逻辑；命中后仅冰箱弹额外散布本体吐息冰刺。
- Impact 统一捕获本体命中及冰刺处理异常；失败先锁定原版 hasImpacted，再停用后端、销毁未销毁的弹体。销毁失败则取消该弹体的 Tick 调度，不重放攻击、不新增清理轮询。
- FridgeBombFrostUtility：接入时校验冰刺 Def，命中时只检查半径 5，均匀无放回抽取最多 24 格；已有冰刺不叠加、不刷新寿命，跳过会清除现有物体的格子。
- FridgeBombSoundPatches：位于主模块，用游戏类型和精确炮弹 Def 补齐缺失的 Explosion_Bomb 音效；不修改本体共享 DamageDef，后端停用也不撤销此补丁。
- FridgeBombVisuals：创建时替换实体 Renderer，回收时还原；逐项容错清理，不修改共享预制体。
- 还原失败时先断开该 Lumi 实例的视觉实体引用，再停用并延迟销毁实体；原版生命周期清理继续执行，但实体不能归池。部分创建失败使用相同路径。
- SupportWorker_FridgeCreepingBombardment：双点选取、方向预览、提交及一次结算；只取消仍属于自己的选点回调。

停用不重复攻击、补扣或退还费用；已提交任务继续由本体管理。缓存 Worker 同样受禁用状态约束。不会卸载已加载的适配程序集，不新增自定义 Tick 或全图扫描；生成的冰刺仍有本体自带的实体、发光和持续伤害开销。冰箱弹不生成家具，不访问天降冰箱组件。

## 当前玩法参数

- 母舰等级 3；研究、356 PowerCoin / 325 VolatileReactive 费用、112500 tick 冷却不变。
- 普通弹仍用本体动作；冰箱弹半径 5、伤害 15，保留 Nivarian_Damage_FrostRanged。
- 每枚冰箱弹在半径 5 内留下最多 24 根 Nivarian_FrostSpike_CoreStrong，单轮最多新增 240 根；复用本体的外观、伤害、减速、寿命及友伤，不复制吐息控制器或中心直击伤害。Debug 的“冰刺生成”日志记录候选数、实际生成数及失败原因。
- 1.7 天降冰箱事件直接查询本体内置 NivarianRefrigerator，无需独立 Draconiture；1.6 仍要求该扩展。既有计时、落点及完成状态不重置。

## 游戏内验证，不使用简易 Test

可开启现有 Debug 总开关查看选点、冰刺生成、音效补齐和回收过程日志，不逐帧或逐 Tick 输出。火力网不再提供接入状态展示、诊断输出或故障模拟按钮，也不统计诊断快照。实际加载校验、异常隔离、资源清理和失败时的一次性警告保留；后端故障后恢复仍需重启游戏。

1. 正常／同版本不同载荷／更新后的本体：确认游戏能加载，接入成功或仅战备停用，没有本模组运行时载荷冲突。
2. 母舰等级 2 时锁定、等级 3 时可用；双点选取、相同点拒绝、取消、连续使用：取消不扣费，成功费用仅结算一次，五组共 20 普通弹、10 冰箱弹，范围圈半径 5。
3. 取消选点、切图及退出游戏会话：自己的预览及换皮应正确清理，不取消其他模组瞄准，不重复攻击。
4. 验证跃迁、拖尾、冰冻伤害、友伤、护盾及对象池还原；交替调用本体战备，普通弹不应残留冰箱外观。检查爆炸不再出现 null SoundDef，已有音效保持不变，后端停用后的在途炮弹仍受音效修复保护。
5. 飞行及轰炸期间存读档、提前销毁、退出地图或游戏、重新开档：检查资源释放与无重复爆炸。
6. 退出游戏后临时移走适配 DLL 再启动：床与原有功能仍可用，战备停用且只警告一次。
7. 仅冰箱弹生成冰刺：每枚最多 24 根、半径 5 内、边缘及障碍格安全跳过；重叠命中不叠加同格冰刺、不续命，伤害/减速/寿命与本体吐息一致，存读档不重复铺设。
8. 不加载独立家具扩展，在 1.7 验证本体内置冰箱可触发原事件；没有合格人物时不计时，已完成的存档不自动重发。

本次不新增、不运行 Test 工程或简易脚本。编译及静态检查不代替实际游戏验证。

保留本体继承，因此适配类型失效时，包含飞行中自定义炮弹的旧档仍可能缺失类型。没有存档迁移或替代载体。
